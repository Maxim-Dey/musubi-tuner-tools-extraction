# Quickstart: Validate Stage-1 Inputs and Noise on CPU

Stage 1 prepares a deterministic validation input/noise component. It does not run a model, calculate validation loss, update weights, write TensorBoard events, or exercise resume state persistence.

## Prerequisites

- Use Python `>=3.10,<3.13` with the project dependencies and pytest installed.
- Run from the repository root with the package installed or `src` on `PYTHONPATH`.
- Use temporary RGB images, UTF-8 captions and small safetensors generated by CPU fixtures. Do not download weights or launch training for this stage.
- For a real dataset, prepare two user-managed nonempty sets and the original Qwen latent/text caches as described in [the contract](contracts/validation-inputs.md). Cache commands accept the same `val-dataset.toml`, but invoking model-backed caching is outside this local acceptance run.

## CPU checks after implementation

In PowerShell:

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
python -m pytest tests/test_qwen_image_validation_inputs.py -q
python -m pytest tests/test_qwen_image_dataset_cache.py tests/test_qwen_image_config.py -q
```

Expected outcomes:

1. Valid role-bearing TOML yields exactly one nonempty `val_familiar` and one nonempty `val_unfamiliar`; both Qwen cache-command preflight paths accept it without reaching a model loader. Legacy unroled train/cache TOML still passes its existing tests.
2. A raw directory image without a required caption fails in either cache-command preflight and trainer preflight. Empty, missing, duplicate or misspelled roles; invalid/unknown fields; conflicting cache-path aliases; missing/corrupt/stale caches; and mismatched metadata fail with source-labelled errors before weights load.
3. Each source occurrence is represented once. Two equal image byte streams have equal SHA-256 `image_id` across roles; distinct content does not. Reordering declarations or relocating unchanged files preserves the canonical input fingerprint and seeds; changing an image, caption, resolution/bucket or cache causes a later comparison/read to fail.
4. For `N1=2`, `N2=1`, the component enumerates exactly two checks with indices `(1,1)` and `(2,1)`, levels `0.275` and `0.725`, and one low and one high level. More generally, there are `(F+U)*N1*N2` checks and `N1/2` levels per half. Seed tests compare against an independently calculated SHA-256 serialization from [the contract](contracts/validation-inputs.md), not the implementation's own helper.
5. Snapshot Python `random`, NumPy, PyTorch CPU and available CUDA RNG states before and after manifest preparation, loader creation and iteration, and epsilon generation. All states remain equal. Noise for the same image/check is stable across roles, reordered inputs and repeated events. The disabled config does not create validation resources.

The associated entities and frozen/read states are defined in [data-model.md](data-model.md). These CPU checks establish input and noise behavior only; real-model numerical verification belongs to a later stage.
