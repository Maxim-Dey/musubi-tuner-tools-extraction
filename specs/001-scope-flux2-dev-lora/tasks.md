## Format and execution rules

- Each checklist item gives an ID, optional `[P]`, story label where applicable, concrete files, prerequisite IDs, a verifiable result and requirement references. Paths are repository-relative. Deletion sets D1-D4 below enumerate exact tracked files; directory headings are path prefixes, not recursive-deletion authorization.
- `[P]` permits concurrent work only after every listed prerequisite is complete and only within the stated disjoint file sets. No task authorizes starting another phase early.
- Use the existing owners and mechanisms. Do not add a validation framework, replacement trainer, public validation command, model registry, benchmark suite or extra training scenario.
- New tests belong to two focused files, `tests/test_flux2_scope.py` and `tests/test_flux2_workflow_contracts.py`, plus meaningful updates to existing tests. Parameterize substantial boundary/regression cases; do not test source spelling, count tests, duplicate existing coverage or copy production validators into tests.

Delete an excluded owner only after its retained callers have been detached. Tests solely for excluded implementations are removed in T027; until then run the explicitly retained suite, without disguising excluded-suite collection errors as passes.

Preserve the original baseline and append comparisons; never overwrite failures with a success summary. Use `passed`, `failed`, `blocked` or `not run` accurately. Concurrent tasks leave their output for the following serial checkpoint to record.
- Use an already equipped supported Python environment with `PYTHONPATH=src`, `PYTHONDONTWRITEBYTECODE=1`, `CUDA_VISIBLE_DEVICES=-1` and `HF_HUB_OFFLINE=1`. Tiny CPU helper/toy-module tests and temporary files are allowed; a training loop or full caching run is not a local smoke test. There are no local tasks for installation/builds, training, GPU execution, downloading weights/resources, server transfer or server verification.
- Missing dependencies currently block the production baseline. Do available read-only checks, record the blocker and keep dependent implementation gates open until comparable baseline evidence is available. Do not install packages, change an optimizer, disable a feature or replace production imports with permissive stubs to manufacture a pass.
