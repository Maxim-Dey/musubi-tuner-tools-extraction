# Контроль: два обучения без валидации

На той же RTX PRO 6000 выполнены **два отдельных обучения по четыре шага**, оба без валидации и генерации изображений. Начальные веса, данные, порядок изображений, шум, seed, расписание и настройки совпали. Проверка уложилась в собственный лимит **8/8 обновлений**; лимит предыдущего прогона 38/38 не менялся.

| Шаг | Потеря A | Потеря B | Разница | Наибольшая разница тензора LoRA |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 0,048516840 | 0,048516840 | 0 | 0 |
| 2 | 0,021230578 | 0,021230578 | 0 | 0,000219906 |
| 3 | 0,099757612 | 0,100336313 | **0,000578701** | 0,000480414 |
| 4 | 0,042662513 | 0,042707242 | 0,000044730 | 0,005177744 |

Веса совпали после первого обновления и начали различаться после второго — первого с ненулевым фактическим темпом обучения. На шаге 3 разница потерь превысила тот же заранее установленный допуск, что применялся в парном сравнении «с валидацией / без валидации». При этом хеши входных латентов, текста, шума и зашумлённых латентов совпали на всех четырёх шагах. Полная сверка весов также обнаружила тензоры за пределами допуска после шагов 2–4.

**Вывод:** сопоставимое расхождение возникает и между двумя запусками без валидации. Поэтому расхождение в [основном прогоне](../20260923T0705Z-b8ed90/verification.md) само по себе не доказывает влияния валидации на обучение. Конкретный источник межпроцессной недетерминированности пока не установлен; исходный критерий G05 остаётся FAIL, его допуск не менялся.
