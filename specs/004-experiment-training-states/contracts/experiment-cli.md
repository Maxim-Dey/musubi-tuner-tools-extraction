# Experiment CLI and Path Contract

Applies only to Qwen-Image `model_version=original` training and its latent/text cache commands when an effective `experiment_dir` is explicitly present. All other invocations keep their current parser, CWD and output behavior.

## Trainer selection and precedence

The trainer retains `--config_file <root>/train.toml`; that file is located relative to the invocation CWD if its argument is relative. Experiment-mode training always requires this selected file, even when `experiment_dir` is absolute: an absolute root removes the need for an anchor but does not authorize CLI-only training. Effective settings merge parser defaults, then that TOML, then explicit CLI values. Add `experiment_dir` as a supported TOML/CLI key. A relative effective root resolves from the selected train TOML's directory. The resolved selected train TOML must be `<root>/train.toml`. No command changes process CWD.

For example, a selected `C:/runs/portrait/train.toml` containing `experiment_dir = "."` resolves to `C:/runs/portrait` regardless of the invocation CWD. If CLI overrides the root, the CLI value wins subject to the selected file still being `<root>/train.toml`; a relative override uses that selected file as anchor. Reject trainer opt-in without `--config_file`, whether the root is relative or absolute, before loading any model.

After root resolution, interpret each relative effective path below from the root; absolute paths remain absolute:

| Trainer setting | Treatment |
| --- | --- |
| `dataset_config`, `val_dataset_config`, `sample_prompts` | Root-relative input files. Experiment-mode training requires enabled validation and both existing train and val dataset TOMLs; missing `val_dataset_config` is an error. |
| `dit`, `vae`, `text_encoder`, `network_weights`, each `base_weights` entry | Root-relative local model/adapter files. |
| `log_tracker_config` | Root-relative local tracker configuration. |
| `resume` | Root-relative local state directory when `resume_from_huggingface` is false; a remote repository identifier is unchanged. |
| `output_dir`, `logging_dir` | Required effective targets: `<root>/output` and `<root>/output/tensorboard`. Fill omissions; reject explicitly supplied alternatives after normalization. |

The existing `output_name` remains a basename used in package names, not a path. In experiment mode reject separators, traversal components or an invalid platform basename before any output is written. No new hidden default for model files is inferred. A conflicting explicit hierarchy assignment fails with the source key/value and the required correction.

## Dataset TOML paths

Within both `train-dataset.toml` and `val-dataset.toml`, resolve relative `image_directory`, `image_jsonl_file`, and `cache_directory` from the same experiment root. Relative `image_path` fields inside JSONL source records also use that root; absolute entries do not change. Preserve the existing image/caption reader, Qwen cache names and role-aware validation. Stage 1 initial preflight and its frozen-item recheck use identical resolution. A relocated unchanged root produces the same portable validation fingerprint.

The train TOML must refer only to unroled training sources. The val TOML must contain the Stage 1 `val_familiar` and `val_unfamiliar` role entries. Caches are generated by selecting each dataset TOML explicitly; validation is never merged into training membership.

## Cache commands

Both Qwen cache entrypoints gain:

- `--train_config <train.toml>`: optional anchor for relative `experiment_dir`, located from invocation CWD. Read only the effective experiment-root field needed by caching; do not parse trainer-only flags as cache flags.
- `--experiment_dir <path>`: explicit cache CLI override. A relative value requires `--train_config`; an absolute value works alone.
- Existing required `--dataset_config <train-dataset.toml|val-dataset.toml>`: in experiment mode, resolve a relative value from the root. Selecting the val file processes both roles through existing role-aware preflight before VAE/text encoder loading.

If `--train_config` supplies `experiment_dir` and no cache CLI override is given, use that value. If neither provides it, retain the existing cache behavior; `--train_config` alone does not silently invent a root. Resolve relative cache model paths `--vae` and `--text_encoder` from the effective root; absolute values remain absolute. The cache commands do **not** accept the trainer's `--config_file` or `--val_dataset_config` as substitutes for `--dataset_config`.

## Experiment-only preflight

Before VAE or text-encoder load, cache commands validate role-aware sources, captions, bucket settings and cache-path collisions; they do not require caches that they are about to create. An absolute cache `--experiment_dir` works without `--train_config`. Before DiT load, the trainer requires its selected `<root>/train.toml`, enabled `val_dataset_config`, both existing dataset TOMLs, and validates their sources/cache bindings, output hierarchy, and configuration constraints. Accept omitted, `float` or `fp32` `save_precision`; reject `fp16`/`bf16` with a correction to `fp32`. `save_last_n_steps` must be a nonnegative integer if supplied; after a successful save/retention, owned current packages older than the inclusive window must be removed whole. Reject explicitly supplied `save_last_n_steps_state`, `save_last_n_epochs`, `save_last_n_epochs_state`, or `save_state_to_huggingface` with the source and correction to remove it and use only `save_last_n_steps` for retention. In experiment mode complete states are unconditional; legacy `save_state` and `save_state_on_train_end` do not create additional states.

Errors identify the effective source (TOML file/field or CLI), cause and correction. These checks do not mutate existing dataset/configuration files.
