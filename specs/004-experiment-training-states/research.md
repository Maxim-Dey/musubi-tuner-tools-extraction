# Research: Portable Experiment and Complete States

## 1. One file for adapter use and exact resume

- **Decision**: Use Accelerate's single safe-serialized `model.safetensors` slot for the unwrapped LoRA `state_dict`, retaining FP32 tensors. Keep the Stage 2 step/protocol sidecar and add one small package sidecar for own-step metrics/ownership; the one best folder supplies the authoritative best score. Verify adapter loading from the exact file and real `accelerator.load_state` in CPU tests.
- **Rationale**: `LoRANetwork.save_weights` serializes `self.state_dict()` and `load_weights` reads tensors with `safetensors.torch.load_file` ([`networks/lora.py`](../../src/musubi_tuner/networks/lora.py), lines 674–683 and 810–833). The Qwen training loader also consumes those tensors through `create_arch_network_from_weights` and `network.load_weights` ([`trainer_base.py`](../../src/musubi_tuner/training/trainer_base.py), lines 1702–1742). Accelerate 1.6 `save_state` writes its first retained model state as `model.safetensors`, followed by optimizer/scheduler and rank RNG files (`accelerator.py` 3248–3305; `checkpointing.py` 100–121, 147–170). The legacy `save_model` additionally calls `network.save_weights` outside the state (trainer base 2059–2099), creating a duplicate if left active.
- **Alternatives considered**: Export a second BF16 adapter alongside the FP32 state (violates one-file requirement); save only BF16 (loses exact FP32 weights); write the same one file manually from the hook with legacy safetensors metadata (allowed fallback only if a real adapter loader requires the metadata). Accelerate's default file carries `format=pt` metadata, whereas legacy export has `ss*`/SAI/hash fields; the project Qwen loader uses tensor keys, so metadata parity is not a stated contract.

## 2. Precision policy

- **Decision**: In experiment mode, accept omitted, `float` and `fp32` `save_precision`; reject effective `fp16`/`bf16` before model loading, with a correction to use FP32. Keep legacy behavior without `experiment_dir`.
- **Rationale**: The trainer sets network dtype FP32 and disables full FP16/BF16 training ([`trainer_base.py`](../../src/musubi_tuner/training/trainer_base.py), lines 1814–1819). Explicit save precision controls the cast in `save_weights` (lora.py 816–820; train_utils.py 238–251). A rounded single BF16 file cannot reconstruct exact FP32 LoRA parameters even if optimizer moments survive.
- **Alternatives considered**: Force BF16 training (disabled and changes mathematics); store hidden FP32 master tensors in another file or optimizer extension (duplicates/complicates the one-file contract); silently ignore `save_precision` (violates effective-configuration errors). The later supplied example must set `save_precision=fp32` or omit it.

## 3. DDP-safe save/load hooks and rank RNG

- **Decision**: Select the actual prepared network by identity/unwrap, replace model weights with one canonical unwrapped network state, and load that state into the unwrapped network on every rank. Require every rank to call `save_state` on the same staging directory and preflight every expected `random_states_<rank>.pkl` before load.
- **Rationale**: The current hook filters prepared models with `isinstance(model, type(unwrap_model(network)))` ([`trainer_base.py`](../../src/musubi_tuner/training/trainer_base.py), lines 1852–1877); a DDP wrapper is not an instance of LoRANetwork, so the model may be removed. Accelerate obtains `get_state_dict(model, unwrap=False)` before calling the hook (`accelerator.py` 3248–3292); an unmodified DDP network would also have `module.` keys unsuitable for direct adapter loading. `load_state` invokes load pre-hooks before normal model/optimizer/RNG restore (`accelerator.py` 3392–3464). Each calling rank writes its own RNG file, but Accelerate catches any RNG-load exception and only logs it (`checkpointing.py` 275–297).
- **Alternatives considered**: Keep the class-based hook (fails DDP); save only on main (loses other ranks' RNG); trust `load_state` success without checking RNG (can silently accept a partial state). The CPU two-rank check must compare restored RNG values, not merely filenames.

## 4. Portable paths and cache CLI

- **Decision**: Resolve a relative experiment root against the selected train TOML's directory; resolve all relative experiment values against the root after defaults → TOML → explicit CLI merging. Add cache `--train_config` and `--experiment_dir`; keep their `--dataset_config` and old CWD behavior when opt-in is absent.
- **Rationale**: The training parser already has `--config_file` and its TOML merge path ([`parser_common.py`](../../src/musubi_tuner/training/parser_common.py), lines 37–49 and 781–810). Both cache parsers currently have only required `--dataset_config` for dataset selection ([`cache_latents.py`](../../src/musubi_tuner/cache_latents.py), lines 170–197; [`cache_text_encoder_outputs.py`](../../src/musubi_tuner/cache_text_encoder_outputs.py), lines 85–96). Their Qwen mains load that file directly before the model. Stage 1's frozen identity omits paths, but its semantic recheck rereads config, so it must receive the same resolver ([`validation_inputs.py`](../../src/musubi_tuner/training/validation_inputs.py), lines 159–204 and 361–375).
- **Alternatives considered**: Change process CWD (leaks into legacy behavior/workers); infer root from dataset filename or fixed example name (not portable); let caches parse the full trainer CLI (unnecessary dependencies and conflicting flags).

## 5. Coalesced sampling and saving

- **Decision**: Determine one set of save reasons at each Stage 2 absolute completed step, then run existing sampling at most once into that step's temporary package before one all-rank state save. A sample-only trigger makes a full package; a new step-0 best receives samples even when `sample_at_first=false`.
- **Rationale**: These two cases are settled in the spec clarifications. Current `sample_images` always writes to `args.output_dir/sample` and exits when `should_sample_images` is false ([`trainer_base.py`](../../src/musubi_tuner/training/trainer_base.py), lines 879–900); the nested `_do_sample` has the same gate (2109–2122). Current sample filenames include epoch/step and timestamp (1012–1020), so duplicate invocations would create distinct PNGs. Stage 2 already has an absolute update boundary (2222–2244) before legacy save/sample calls (2246–2271).
- **Alternatives considered**: Keep detached samples in output/sample (violates package ownership); discard sample-only triggers (violates clarification); create a second package later for best (violates one package/step). Add a narrow destination/force seam rather than a second inference implementation.

## 6. Publication, best and retention

- **Decision**: Stage one whole package under experiment output; validate required files and samples; rename to current or best only after completion. Preserve the old best until the new best package is complete. Track best by one complete package in `val-loss/` and its sidecar; move directories, never copy or hard-link. Prune only owned complete current packages older than `X-save_last_n_steps`, keeping equality and the best.
- **Rationale**: Existing separate model and state retention in `trainer_base.py` 2255–2277 and `train_utils.py` 176–207 cannot implement whole-package retention. A staging folder avoids exposing incomplete state and lets an error leave the prior best intact. A single physical directory location avoids duplicated weights/samples.
- **Alternatives considered**: Keep current and best copies (violates uniqueness); independent model/state retention (can destroy resumability); general transactional or content-addressed storage (unneeded). Directory renames across current/best under one output volume are sufficient for the controlled local requirement; an abrupt crash during a multi-directory best exchange is not claimed to be an atomic transaction.

## 7. Resume from an older current state

- **Decision**: Use the loaded package sidecar for its own absolute step, protocol and local metrics, and independently read the existing best package for the comparison baseline. Reject inconsistent best/ownership metadata or a conflicting existing package at a future step; do not overwrite old weights.
- **Rationale**: Stage 2's `val_loss_state.json` binds the loaded absolute step and validation fingerprint ([`validation_state.py`](../../src/musubi_tuner/training/validation_state.py), lines 56–68 and 99–130). A best record in an older loaded current package may predate a later best. Assigning the later best's metric to the loaded model would misattribute results; resetting best to infinity could replace a genuinely better state.
- **Alternatives considered**: Treat loaded step's score as current best (wrong for older current resume); overwrite later checkpoints when replaying from an older step (breaks unique step identity); infer step from optimizer/scheduler (Stage 2 rejects that).
