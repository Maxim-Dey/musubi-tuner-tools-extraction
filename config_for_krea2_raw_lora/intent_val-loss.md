# Krea2 Raw LoRA: детерминированный val-loss и организация эксперимента

## Область изменений и текущее состояние

Этот интент описывает будущую доработку обучения LoRA для **Krea2 Raw**. Пример Qwen Image используется как образец организации эксперимента и параметров валидации.

- Точка входа — `krea2_train_network.py`, тренер — `Krea2NetworkTrainer`, модуль LoRA — `networks.lora_krea2`.
- Базовая модель — Krea2 Raw DiT. Сохраняются необходимые ей **Qwen-Image VAE** и **Qwen3-VL-4B-Instruct**. Текстовый энкодер Qwen2.5-VL-7B из примера Qwen Image не подходит.
- Поддерживается обучение по изображениям с описаниями. Не переносить режимы Qwen Image Edit, параметры `model_version`, `fp8_vl` и модуль `networks.lora_qwen_image`.
- Для обучения сохранить `timestep_sampling = "krea2_shift"`: его shift зависит от разрешения. Фиксированный `discrete_flow_shift = 2.2` из примера не требуется при этом режиме. Сам параметр `discrete_flow_shift` общий, но относится к другим настройкам распределения.
- `fp8_base`, `fp8_scaled`, `blocks_to_swap`, SDPA и gradient checkpointing поддерживаются Krea2. FP8 включается только парой `fp8_base = true`, `fp8_scaled = true`; ConvRot INT8 — отдельная, несовместимая с FP8 альтернатива.
- В текущей ветке **ещё нет** `experiment_mode`, `auto_cache`, `val_dataset_config` и параметров `val_`*. Неизвестные ключи TOML отклоняются. В текущем `train.toml` будущие параметры оставлены комментариями; обучение пока использует вручную подготовленные кэши и пути от рабочей директории.
- Реализация этого интента должна добавить описанные параметры и поведение. Без режима эксперимента существующий запуск обучения должен оставаться доступным.

## Валидационный датасет

- Пользователь самостоятельно подготавливает непустой датасет `val`: изображения с описаниями, не участвующие в обучении. Он задаётся отдельным `val_dataset_config`.
- Train нужен для обучения; описанные ниже метрики рассчитываются только на `val`. Второй валидационный датасет не требуется.
- Изображения, описания, разрешения/buckets, обработка и соответствующие кэши `val` фиксируются на протяжении обучения, включая resume. Случайные аугментации, изменение описаний и автоматическая подмена входов валидации запрещены.
- При изменении зафиксированных входов или несовместимости кэша выдавать понятную ошибку до продолжения обучения. При resume не пересоздавать незаметно другой набор входов валидации.
- `id_изображения = SHA-256 содержимого исходного файла`; он не зависит от имени, пути, порядка загрузки и перезапуска. Копии одного изображения в train и val не должны допускать утечку обучающих данных в валидацию.
- Для val использовать `batch_size = 1`, `num_repeats = 1`: каждое уникальное изображение учитывается один раз за проход. Train-батч и число повторов обучения задаются независимо.
- До загрузки модели проверять параметры валидации, доступность конфигов, непустоту train и val, отсутствие пересечения изображений и совместимость имеющихся кэшей.

## Параметры будущей валидации

Все параметры задаются в основном `train.toml`.

| Параметр             | Назначение                                                         | Пример               |
| -------------------- | ------------------------------------------------------------------ | -------------------- |
| `experiment_mode`    | Пути и структура результатов относительно папки эксперимента       | `true`               |
| `auto_cache`         | Подготовить недостающие совместимые train/val кэши до загрузки DiT | `true`               |
| `val_dataset_config` | Конфиг отдельного валидационного датасета                          | `"val-dataset.toml"` |
| `val_every_n_steps`  | Период в завершённых шагах оптимизатора, целое ≥ 1                 | `10`                 |
| `val_seed_noise`     | Общий целочисленный seed валидационного шума                       | `42`                 |
| `val_level_noise_n`  | Число уровней шума `N1`, чётное целое ≥ 2                          | `10`                 |
| `val_seed_noise_n`   | Число реализаций шума на уровне `N2`, целое ≥ 1                    | `2`                  |

Наличие `val_dataset_config` включает валидацию; без него обучение работает без val-loss. Неполный набор явно заданных настроек валидации должен вызывать понятную ошибку, а не молча отключать проверку. `sample_at_first` и `sample_every_n_steps` управляют только генерацией изображений.

## Периодичность и режим выполнения

- В новом запуске валидация выполняется до первого обновления весов — шаг 0.
- Далее — после каждых `val_every_n_steps` завершённых шагов оптимизатора, после накопления градиентов и до следующего обучающего шага.
- После последнего шага обучения выполняется итоговая валидация. Если этот шаг уже проверен периодически, повторный проход не нужен.
- При resume стартовая проверка относится к восстановленному шагу `S`, а не к шагу 0; уже сохранённую точку для того же состояния не дублировать. Периодический график продолжать по общему счётчику шагов.
- Размер батча валидации всегда 1. DiT и LoRA переводятся в режим оценки, все виды dropout отключаются. После прохода, в том числе при ошибке, восстанавливаются предыдущие режимы, gradient checkpointing и состояние block swap, если они использовались.
- Валидация выполняется без расчёта градиентов, обновления весов, scheduler и состояния оптимизатора. Не накапливать градиенты через ветку gradient checkpointing в `call_dit`.
- Шум формируется отдельным генератором. Весь проход должен сохранять состояния RNG обучения: Python, NumPy, PyTorch CPU и используемых CUDA-устройств.
- При нескольких GPU изображения учитываются ровно один раз; итоговые метрики и их шаг должны совпадать с однопроцессным расчётом с допустимой численной погрешностью. В TensorBoard записывает основной процесс.

## Детерминированный шум и интерфейс Krea2

- Для каждого изображения val выполняется `N1 × N2` проверок.
- Диапазон `0.05–0.95` делится на `N1` равных интервалов. Используются их середины: `t_i = 0.05 + (i - 0.5) × 0.90 / N1`, где `i = 1…N1`.
- Группы: `low noise` — `0.05 ≤ t < 0.5`, `high noise` — `0.5 ≤ t ≤ 0.95`. При чётном `N1` в каждой группе одинаковое число уровней.
- `t` — конечный коэффициент шума: `x_t = (1 - t) × latents + t × noise`, где `noise` — стандартный нормальный шум той же формы, что и латент.
- В `Krea2NetworkTrainer.call_dit` передаётся `timesteps = 1000 × t`. Этот метод делит значение на 1000, и Krea2 DiT получает `t` в шкале `0–1`.
- Не применять к фиксированным уровням `krea2_shift`, другой shift, случайное распределение или ограничения train-таймстепов. В текущем общем `get_noisy_model_input_and_timesteps` дополнительно применяется `+1`, а входные `timesteps` используются как исходные случайные значения для распределения. Поэтому для val нужно напрямую сформировать `x_t` и `1000 × t`, без вызова этого преобразования и без `+1`. Это требование к новому пути валидации, а не указание менять обучение в рамках правки конфигов.
- Seed каждой проверки: `stable_hash(val_seed_noise, id_изображения, i, j)`, где `j = 1…N2`. Реализовать через `hashlib.sha256` с однозначной сериализацией аргументов и фиксированным преобразованием digest в целое допустимого диапазона генератора; не использовать встроенный `hash()` Python.
- Один и тот же набор шума используется на каждом шаге валидации и после resume. Точность и устройство генерации шума должны оставаться согласованными в пределах эксперимента.

## Расчёт и усреднение loss

- Используются нормализованные латенты Qwen-Image VAE и текстовые представления Qwen3-VL из кэшей **Krea2**, как при обучении.
- Прямой проход использует Krea2 patchification, позиции и маски текстовых токенов из `call_dit`. Не подменять его Qwen Image forward или генерацией картинки через семплер.
- Цель flow matching — `noise - latents`. Расчёт ошибки тот же, что при обучении: MSE и выбранное `weighting_scheme`; в текущем конфиге `"none"`, то есть без дополнительного взвешивания. CFG для val-loss не применяется.
- Для каждой проверки усреднить ошибку по элементам латента. Для каждого изображения усреднить все `N1 × N2` проверок, затем усреднить результаты по уникальным изображениям val с равными весами.
- `loss_low_noise` и `loss_high_noise` вычисляются аналогично по соответствующим уровням. `loss_mean` учитывает все уровни.

## TensorBoard и resume

К существующим графикам обучения добавить три скалярных графика:

| График | Содержание |
| --- | --- |
| `val_loss_mean` | Loss на val, усреднённый по всем уровням, реализациям шума и изображениям |
| `val_loss_low_noise` | Loss на val для low noise |
| `val_loss_high_noise` | Loss на val для high noise |

- Включить `log_with = "tensorboard"`, задать `logging_dir` и `log_prefix` в конфиге. Для запуска требуется пакет TensorBoard.
- Ось X — число завершённых шагов оптимизатора, не микробатчей. При resume восстановить этот счётчик, веса LoRA, optimizer, scheduler и RNG; графики train-loss и val-loss продолжаются с восстановленного шага.
- Сохранять сведения, необходимые для восстановления шага, позиции обучения и уже выполненной валидации. Не считать, что шаг оптимизатора всегда равен внутреннему счётчику Accelerate, особенно при gradient accumulation.
- `network_weights` загружает только адаптер и не заменяет `resume` состояния обучения.

## Папка эксперимента, пути и кэширование

- Пользователь создаёт папку с произвольным названием и помещает в неё конфиги, промпты и датасеты. Один каталог соответствует одному эксперименту.
- При `experiment_mode = true` относительные пути основного конфига, включая модели и `resume`, считаются от папки `train.toml`. Пути внутри dataset TOML — от папки соответствующего TOML; абсолютные пути сохраняются.
- В основном конфиге использовать `dataset_config = "train-dataset.toml"`, `val_dataset_config = "val-dataset.toml"`, `sample_prompts = "sample_prompts.txt"`, `output_dir = "output"`, `logging_dir = "output/tensorboard"`.
- Текущий `dataset.toml` остаётся конфигом запуска без режима эксперимента. При переходе подготовить `train-dataset.toml` и `val-dataset.toml`, обновив пути внутри них; одного переименования недостаточно.
- `auto_cache = true` должен использовать существующую логику `krea2_cache_latents.py` и `krea2_cache_text_encoder_outputs.py` для train и val с теми же VAE и энкодером, что указаны в `train.toml`. Перед загрузкой DiT освободить память моделей кэширования.
- Train и val используют отдельные каталоги кэша. Готовые совместимые кэши повторно не вычисляются; кэши Qwen Image не принимаются как кэши Krea2. При `auto_cache = false` отсутствие нужного кэша вызывает понятную ошибку до обучения.
- Имена кэшей соответствуют текущему формату: `<имя>_<width>x<height>_kr2.safetensors` для латентов и `<имя>_kr2_te.safetensors` для текста. В имени латентного кэша используются исходные размеры изображения с минимум четырьмя цифрами, а не размер bucket. Метаданные архитектуры — `krea2`, текстовый тензор — `varlen_krea2_vl_embed_<dtype>`.

## Чекпоинты и семплы

- При `save_state = true` сохранять одну папку на шаг с LoRA, optimizer, scheduler, RNG и данными продолжения. Не создавать рядом вторую копию адаптера. При совпадении периодического и финального сохранения не дублировать состояние того же шага.
- Единственный возобновляемый адаптер должен сохраняться в FP32 (`save_precision = "fp32"`), даже при `mixed_precision = "bf16"`. Сохранение должно оставаться совместимым с загрузкой LoRA и resume.
- `save_last_n_steps` — окно хранения в шагах, а не число чекпоинтов. `save_last_n_steps_state`, если задан, переопределяет окно для state. Это не нижняя и верхняя границы одного диапазона.
- Для единой папки без дубликата LoRA использовать одно окно хранения: `save_last_n_steps_state`, если задан, иначе `save_last_n_steps`; удалять устаревшую папку целиком вместе с её семплами. В предлагаемом конфиге оба значения равны 1000. При отсутствии обоих ограничений сохранять все папки.
- Сохранение state в конце сохраняется; финальная папка должна содержать фактический последний шаг даже при его несовпадении с периодом сохранения.
- Для описанной структуры семплов задавать `sample_every_n_steps = save_every_n_steps`; в примере Krea это 200. Если интервалы различаются или включён `sample_at_first`, семплы шага без чекпоинта сохранять отдельно с его номером, не приписывая их другим весам.
- Семплы строятся Krea2 Raw с текущей LoRA. Они не участвуют в расчёте val-loss. Выбор AdamW или AdamW8bit не зависит от архитектуры; в текущем черновике сохранён AdamW.
- В `sample_prompts.txt` использовать поддерживаемые флаги `--w`, `--h`, `--d`, `--s`, `--l` и необязательный `--n`. Пользовательские семплы генерируются без отрицательного промпта: при отсутствии `--n` тренер кодирует пустую строку для безусловной ветки CFG. Для семплов заданы `--l 4.5 --s 52`: эквивалент официального примера Krea2 Raw с guidance 3.5 и 52 шагами. Значение `--l 1` отключает CFG. Флаг `--fs` не поддерживается: расписание Krea2 Raw зависит от разрешения автоматически.

- `dataset/train/` содержит 107 изображений с соответствующими `.txt`-описаниями; `dataset/val/` — 20 изображений с `.txt`-описаниями.
- Использовать этот датасет для проверки обучения, val-loss и resume. Сохранить предоставленное разделение train/val, имена файлов и описания; автоматически переразбивать датасет не нужно.

## Готовность Pod к самостоятельному обучению

- Результат работы агента — подготовленный и проверенный инструмент на Pod. После тестовых прогонов пользователь должен иметь возможность подключиться по SSH и самостоятельно запустить обучение без дополнительной установки и настройки.
- Оставить на Pod рабочий код, установленное окружение со всеми зависимостями, необходимые модели и файлы токенизатора, датасет, подготовленные train/val кэши и конфиги с действительными путями.
- Тестовые конфиги, логи и чекпоинты хранить отдельно от результатов пользовательского обучения. Подготовить основной конфиг для самостоятельного запуска; не оставлять в нём временные ограничения тестового прогона или автоматический resume из тестового состояния.
- Передать пользователю точную рабочую директорию и готовые команды активации окружения, запуска нового обучения, resume и TensorBoard. Полноценное обучение после тестов пользователь запускает самостоятельно.
- После тестовых прогонов завершить тестовые процессы обучения и освободить GPU. Подготовленное окружение и данные сохранить; Pod не выключать.
- Порт **6006** для TensorBoard уже открыт пользователем. Агент должен настроить и запустить TensorBoard с прослушиванием `0.0.0.0:6006`, указать каталог логов пользовательского эксперимента, проверить доступность и сообщить пользователю фактический адрес. TensorBoard должен оставаться доступным после завершения SSH-сессии агента и отображать логи последующего пользовательского обучения.
