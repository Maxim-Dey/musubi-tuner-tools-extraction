# Команды Spec Kit: только обучение LoRA для Krea2 Raw

Выполни команды ниже последовательно. Работай только в ветке `codex/krea2-raw-lora-only`; другие ветки и рабочие деревья, включая Qwen Image, не изменяй. Директория фичи: `specs/003-krea2-raw-lora-only`. При повторном запуске продолжай эту фичу, не создавая дубликаты.

Соблюдай `.specify/memory/constitution.md`. Не создавай конституцию заново и не изменяй её без моего отдельного согласия. Документы Spec Kit пиши на английском, ответы мне — на русском. Обычные технические решения и переходы между этапами выполняй самостоятельно.

## 1. Спецификация

```text
$speckit-specify

SPECIFY_FEATURE_DIRECTORY=specs/003-krea2-raw-lora-only

Первая фича: оставить в репозитории только код обучения LoRA для Krea2 Raw и необходимые для этого компоненты. Добавить стартовую конфигурацию для запуска такого обучения.

Используй ветку codex/krea2-raw-lora-only. Создай или обнови только спецификацию этой фичи и назначь её текущей средствами Spec Kit. Документы других фич не переписывай. Конституцию не изменяй.

Сохрани полный процесс: датасет изображений с подписями, кеширование латентов и текстовых представлений, обучение LoRA, контрольные изображения на Raw во время обучения, логирование, сохранение LoRA и состояния обучения, возобновление. Сохрани существующие применимые к этому процессу настройки и оптимизации, даже если они выключены в стартовом примере.

Удали реализации и точки запуска обучения других моделей, full fine-tuning, видео, image-edit и остальные самостоятельные сценарии вне указанного процесса. Удали поддержку Krea2 Turbo и отдельные команды генерации, сохранив генерацию контрольных изображений на Raw внутри обучения. Удали относящиеся только к исключённым сценариям конфиги, документацию, тесты и зависимости. Недостаточно удалить корневые скрипты или запретить режимы, оставив их реализации.

Необходимые общие компоненты сохрани в минимальном объёме. В частности, Qwen-Image VAE и Qwen3-VL нужны Krea2 Raw; их сохранение не означает сохранение обучения Qwen Image. Определяй необходимость по использованию, а не по названию файла или архитектуры.

Создай согласованный стартовый комплект:
- config_for_krea2_raw_lora/train.toml;
- config_for_krea2_raw_lora/dataset.toml;
- config_for_krea2_raw_lora/sample_prompts.txt.

Параметры должны поддерживаться фактическим кодом. После замены явно обозначенных пользовательских путей и подписей комплект должен позволять выполнить описанные в README кеширование и обучение. Значения разрешения, rank, длительности и путей в примере не должны становиться ограничениями программы. Не обещай совместимость с неизвестным оборудованием.

Удаление остальных моделей и режимов — явно разрешённое несовместимое изменение. Для остающегося процесса сохрани смысл настроек, алгоритм обучения, форматы датасета, кешей, LoRA и состояния возобновления. Не добавляй новый framework, универсальные абстракции, посторонние функции или бенчмарки.

Критерии приёмки: весь указанный процесс сохранён; лишние реализации удалены; оставшиеся команды не зависят от удалённых модулей; стартовые файлы согласованы с реальными парсерами и друг с другом; неизвестные параметры и исключённые режимы отклоняются до загрузки модели; README описывает только поддерживаемый процесс и рабочие примеры команд.

Сохрани Git, лицензии, пользовательские данные, инфраструктуру Spec Kit и этот файл промптов. Объём работы — локальная реализация и доступные локальные проверки. Не запускай обучение, GPU-прогоны, скачивание весов, сборку пакетов или удалённую проверку. Проверки без весов не считать подтверждением реального обучения.
```

## 2. План

```text

Krea2 сейчас получает общие функции через hv_train_network.py, хотя базовые компоненты уже есть в training. Используй существующие общие модули и переноси только действительно необходимое поведение до удаления чужих подсистем.

В research.md и plan.md перечисли конкретные компоненты: сохранить, минимально адаптировать, удалить — с причиной. Учти корневые обёртки, src, документы, примеры, тесты, зависимости и имеющиеся lock-файлы. Не сохраняй целые реализации исключённых моделей под видом общих модулей. Не переименовывай компоненты без необходимости.

Определи содержимое трёх стартовых файлов по коду и документации Krea2 Raw. Проверь все параметры через реальные парсеры и их потребителей, включая network_module, сочетания optimizer/scheduler, precision и настроек экономии памяти. Не копируй настройки Qwen автоматически. Явно обозначь пользовательские замены, согласуй относительные пути и команды запуска из корня репозитория.

Опиши применение defaults → TOML → CLI и проверку итоговой конфигурации. Неизвестные ключи, неподдерживаемые режимы и несовместимые сочетания должны давать понятную раннюю ошибку; отдельно учти значения из TOML. Не удаляй проблемные параметры и не отключай функции ради успешной проверки.

В quickstart.md укажи подготовку датасета, команды обоих кешей, обучение из стартового конфига, контрольные изображения, сохранение и resume. Команды реального запуска здесь только документируй.

Перед изменением существенной логики зафиксируй исходное поведение доступными локальными проверками. Предусмотри проверки реальных импортов, парсеров, конфигов и значимых регрессий без GPU, весов и сетевых обращений в тестах. Не ограничивай проверку поиском строк и не подменяй всю проверяемую цепочку заглушками. Не добавляй тесты ради покрытия.
```

## 6. Проверка завершённости

```text
$speckit-converge

Сверь фактическую реализацию specs/003-krea2-raw-lora-only с каждым требованием спецификации, решением плана, задачами и конституцией. Не полагайся только на отметки в tasks.md.

Проверь сохранность всего процесса Krea2 Raw LoRA и его оптимизаций, корректность трёх стартовых файлов, отсутствие посторонних реализаций и зависимостей от удалённых модулей, ранние ошибки конфигурации, README и результаты обязательных локальных проверок.

При подтверждённых расхождениях только добавь новые задачи в конец tasks.md по правилам converge. Для каждого укажи требование, доказательство, влияние, исправление и критерий проверки. Не добавляй задачи по стилю, предположениям или новым функциям и не дублируй незакрытые задачи.

Внутри converge не изменяй код, spec.md, plan.md, конституцию и существующие задачи. Если расхождений нет, оставь tasks.md без изменений.
```

Если converge выявил недоработки, отдельным шагом выполни `$speckit-implement` для добавленных задач, проведи соответствующие проверки и повтори `$speckit-converge`. Соблюдай общий лимит двух раундов исправлений. Дополнительное согласование этих раундов не требуется. Если лимит исчерпан, прекрати исправления и перечисли оставшиеся подтверждённые дефекты, не объявляя работу завершённой.

Локальный этап завершён только при выполненных требованиях, пройденных обязательных локальных проверках и актуальном README. Отсутствие реального GPU-прогона укажи один раз в итоговом результате.
